## Top 5

1. **AI agent posture risk scoring in Defender (Preview)**{{< cat "Security & Compliance" >}} - If your organization is deploying enterprise or local AI agents, Defender can now assess their risk posture using configuration, access, runtime activity, and alert signals. This is the first structured way to prioritize which agents represent active security exposure before something goes wrong.

2. **Real-time protection for Agent 365 tooling servers (GA)**{{< cat "Security & Compliance" >}} - Defender now evaluates and can block tool invocations against security policies for Work IQ MCP and customer MCP tools in Agent 365. This is production-grade control over what your agents can actually do at runtime, and it shipped GA this week.

3. **Threat detection for Agent 365 agents (Preview)**{{< cat "Security & Compliance" >}} - Runtime signals from Copilot Studio, Microsoft Foundry, and Agent Builder are now flowing into Defender XDR as incidents and advanced hunting data. Security teams can finally investigate AI agent behavior the same way they investigate endpoint activity.

4. **Purview DLP for Copilot prompts reaches government clouds (GA)**{{< cat "Security & Compliance" >}} - The real-time DLP control that blocks Copilot from responding when prompts contain sensitive data is now available in government cloud tenants. If you manage a GCC, GCC-High, or DoD environment, this capability is live and worth validating against your DLP policies.

5. **DLP block for external domains and users in SharePoint/OneDrive (Preview)**{{< cat "Security & Compliance" >}} - Admins can now configure DLP policies that block specific external domains or individual users from accessing sensitive files, rather than relying on broad sharing controls. This fills a meaningful gap in external data leakage prevention.

## Identity & Access

- **[(GA) Domain investigation page in Defender for Identity](https://learn.microsoft.com/en-us/defender-for-identity/investigate-domain)** [GA] - The dedicated Active Directory domain investigation page is now generally available, surfacing domain properties, deployment health, identity summary, service account breakdown, sensitive entities, group policies, and trust relationships in one place. This meaningfully accelerates lateral movement investigations that span domain boundaries. Analysts should bookmark this view and incorporate it into Active Directory incident runbooks.

## Security & Compliance

- **[(Preview) AI agent posture risk in Microsoft Defender](https://learn.microsoft.com/en-us/defender-xdr/security-for-ai/ai-agent-risk-assessment)** [Preview] - If you are deploying AI agents, Defender now gives you a structured posture risk view covering configuration, access, runtime activity, endpoint and user context, and active alerts. Risk levels map directly to prioritized recommendations, so your SOC and AI teams have a shared starting point for agent hardening. Review the posture dashboard now to understand your current agent exposure before enforcement conversations begin.

- **[(Preview) Threat detection for Microsoft Agent 365 agents](https://learn.microsoft.com/en-us/defender-xdr/security-for-ai/ai-agent-detection-protection)** [Preview] - Defender XDR now analyzes runtime signals from agent interactions, tool usage, and execution patterns across Copilot Studio, Microsoft Foundry, Agent Builder, and SDK-integrated agents, surfacing results as incidents and advanced hunting data. This closes a major visibility gap for organizations running production AI workloads. Enroll in the preview and establish a baseline hunting query set for your deployed agents.

- **[(GA) Real-time protection for Microsoft Agent 365 tooling servers](https://learn.microsoft.com/en-us/defender-xdr/security-for-ai/ai-agent-real-time-protection)** [GA] - Defender now enforces security policies on tool invocations between agents and MCP servers, with the ability to allow or block interactions in real time. This is the enforcement layer that complements posture risk scoring and threat detection. Define your policy stance for MCP tool categories now so the enforcement behavior matches your risk tolerance from day one.

- **[From open lures to cloaked gates: How a macOS ClickFix campaign learned to hide](https://www.microsoft.com/en-us/security/blog/2026/08/05/macos-clickfix-campaign-learned-hide/)** [GA] - A macOS ClickFix infostealer campaign added browser fingerprinting to gate malicious payloads, making infrastructure scanning less effective for detection. The blog details the new hunting indicators that the technique shift introduces. Security teams managing macOS fleets should review the indicators and adjust endpoint detections accordingly.

- **[Secure the AI Model, Not Just Access](https://www.youtube.com/shorts/FSkgiTgwfmY)** [GA] - Microsoft Mechanics covers the Zero Trust principle that AI resources including models, agents, APIs, and data pipelines need to be secured as resources themselves, not just gated at the access layer. Prompt Shields and runtime protections via Microsoft Foundry are the recommended controls. Worth sharing with any architecture or AI team still treating identity as the only AI security lever.

- **[Make Protection Follow Your Data](https://www.youtube.com/shorts/6bnQzzRmYaU)** [GA] - This Mechanics short covers how Purview sensitivity labels applied to unstructured M365 data extend into Microsoft Fabric and other cloud data stores, including AI workloads. The practical takeaway is that label-driven encryption and DLP intent travels with data outside the M365 boundary. If your Fabric or AI pipeline governance story relies on separate controls, this is worth a review.

- **[Microsoft Purview: Role groups UI enhancements](https://www.microsoft.com/microsoft-365/roadmap?id=562033)** [Preview] - The Purview compliance portal Role groups page now lets admins look up permissions by roles and memberships directly in the UI. This reduces the operational overhead of auditing who has what compliance permissions. Preview is available now; GA is targeted for July 2026.

- **[Microsoft Purview DLP for Microsoft 365 Copilot in government clouds](https://www.microsoft.com/microsoft-365/roadmap?id=561892)** [GA] - Real-time DLP for Copilot prompts, which blocks responses when prompts contain sensitive data and prevents that data from being used for grounding, is now GA in government clouds. GCC, GCC-High, and DoD tenant admins should audit existing DLP policies to ensure Copilot prompt locations are covered. This shipped in June 2026.

- **[Microsoft Purview DLP: Block external domain/user action for SharePoint and OneDrive](https://www.microsoft.com/microsoft-365/roadmap?id=557191)** [Preview] - DLP policies can now target specific external domains or individual external users for file access blocking in SharePoint and OneDrive, adding precision beyond tenant-wide external sharing settings. This is the right tool for organizations that need to block specific partners or individuals from sensitive document libraries without disrupting all external sharing. Preview is active; GA is targeted for July 2026.

## Action Required

- **[DLP for Copilot prompts in government clouds: Validate coverage now](https://www.microsoft.com/microsoft-365/roadmap?id=561892)** - GA as of June 2026. If you operate a GCC, GCC-High, or DoD tenant, confirm that your existing DLP policies include Copilot prompt locations. The feature is live and unprotected prompts containing sensitive data represent an active compliance gap if policies have not been extended.

- **[Real-time Agent 365 MCP tool protection: Define policy stance before defaults bite you](https://learn.microsoft.com/en-us/defender-xdr/security-for-ai/ai-agent-real-time-protection)** - GA as of this week. Organizations using Work IQ MCP or customer MCP tools with Agent 365 should document their intended allow/block posture per tool category and configure Defender policies accordingly. Leaving enforcement at defaults without intentional configuration is a governance gap.

- **[macOS ClickFix campaign: Review endpoint detections for fingerprinting-gated payloads](https://www.microsoft.com/en-us/security/blog/2026/08/05/macos-clickfix-campaign-learned-hide/)** - Active campaign targeting macOS. Review the Microsoft Security Blog indicators of compromise, update Defender for Endpoint custom detections for macOS, and confirm your browser fingerprinting-aware hunting queries are current. This technique shift reduces the effectiveness of passive infrastructure scanning alone.
