## Top 5

1. **Copilot Studio agent governance deep-dive published:** {{< cat "Action Required" >}} {{< reason "Governance Move" >}} With agent user accounts now giving Copilot Studio agents their own M365 identity, directory profile, and Teams/Outlook presence, Microsoft's published governance guide is required reading. Twenty-nine percent of employees are already using unsanctioned AI agents, and 32% of surveyed orgs have had data security incidents involving generative AI tools. Lock down agent access, scoped permissions, and cost controls before your makers get too far ahead.

2. **Windows Autopatch granular update controls in preview:** {{< cat "Endpoint & Device Management" >}} {{< reason "New Capability" >}} A single quality update policy in Intune can now independently govern Windows quality updates, .NET Framework updates, and quick machine recovery updates with per-type automatic or manual approval. This is the update control model many orgs have been waiting for; enroll your pilot ring now and evaluate the new Autopatch reports before broad rollout.

3. **Microsoft data governance strategy pivots to Microsoft Fabric:** {{< cat "Security & Compliance" >}} {{< reason "Worth Watching" >}} Microsoft has announced that the next chapter of its data governance strategy moves natively into Microsoft Fabric, with the OneLake catalog becoming the unified governance foundation. If your org has Purview standalone investments or a roadmap built around the classic data catalog, this shift in platform direction deserves a strategy review.

4. **AI supply chain attacks targeting coding agents documented by Microsoft Research:** {{< cat "Security & Compliance" >}} {{< reason "Worth Watching" >}} Microsoft's AI Red Team detailed how poisoned datasets and model checkpoints can trigger remote code execution in coding agents by editing fewer than ten neurons. While no immediate patch action is required, orgs deploying third-party or fine-tuned coding agents should review their model sourcing and supply chain controls.

5. **CIS benchmark auditing for Windows 11 in Intune (public preview):** {{< cat "Endpoint & Device Management" >}} {{< reason "New Capability" >}} Intune Advanced Analytics subscribers can now audit Windows 11 devices against the CIS Microsoft Intune for Windows 11 Benchmark, with per-setting results and export capability. This is audit-only and does not remediate, but it closes a long-standing gap for orgs that need evidence-based compliance reporting against a recognized benchmark.

## Endpoint & Device Management

- **[Share device diagnostics during Remote Help sessions on Windows](https://learn.microsoft.com/en-us/intune/remote-help/start-session#use-diagnostic-data-reports-in-attended-windows-sessions)** [GA] - Helpdesk agents can now review system details and resource usage during attended Remote Help sessions on Windows, with explicit end-user consent required and user control to stop sharing at any time. Declining the diagnostic request does not terminate the session, so support can continue regardless. Roll this out to your helpdesk tier and update your Remote Help user communications to set expectations around the new consent prompt.

- **[Keep work files in OneDrive for Business with Edge for Business on Windows](https://learn.microsoft.com/en-us/intune/app-management/protection/ref-settings-windows#data-transfer)** [GA] {{< emphasis "Data" >}} - Edge for Business on Windows can now be forced to save downloaded work files to OneDrive for Business instead of local disk via app protection policy. Set "Send org data to" to "Selected apps" and add OneDrive for Business as the destination; requires Edge version 158 or later. This closes a meaningful data exfiltration path for managed Windows devices where local download folders were previously uncontrolled.

- **[New and updated settings for Windows in the settings catalog](https://learn.microsoft.com/en-us/deployedge/microsoft-edge-policies)** [GA] - The Windows settings catalog now includes refreshed Microsoft Edge (155+) and Google Chrome (153.0.8010.53) administrative templates, plus new Cloud PC device reset settings. Review the updated Edge policy text for any behavior changes before your next settings catalog profile update cycle.

- **[Automate tasks with local actions on Android Enterprise devices](https://learn.microsoft.com/en-us/intune/device-management/tools/run-powershell-scripts-windows)** [GA] - Intune now supports local automation triggers on Android Enterprise fully managed and dedicated devices, covering device restarts, Managed Home Screen sign-in/sign-out, power connection changes, and scheduled times, with up to five actions per event including app launches, broadcast intents, and MHS sign-out. This is particularly useful for kiosk and frontline worker deployments where consistent device state after each shift or restart is critical.

- **[Require Google Workspace authentication on Android Enterprise devices](https://techcommunity.microsoft.com/blog/intunecustomersuccess/require-google-workspace-authentication-on-android-enterprise-devices-with-micro/4565954)** [GA] - Intune now supports requiring managed Google Account authentication on personally owned Android Enterprise work profile devices, extending a capability previously limited to corporate-owned fully managed and work profile devices. This gives users access to org-assigned Google apps and services without changing the Entra account tied to the Intune-managed device. Useful for orgs with mixed personal/corporate Android fleets that also use Google Workspace.

- **[Increase Intune management agent check-ins on macOS](https://learn.microsoft.com/en-us/intune/device-configuration/troubleshoot-device-profiles#policy-refresh-intervals)** [GA] - macOS Intune agent check-in frequency changes significantly: newly enrolled devices check every three minutes for 15 minutes, then every 15 minutes for two hours, then settle into a new standard cadence of approximately one hour (down from roughly eight hours). No admin or user action is needed, but expect faster policy and app delivery to macOS endpoints, which may also accelerate compliance state changes you should be prepared to monitor.

- **[Maintenance windows for operating system and driver updates on Windows](https://learn.microsoft.com/en-us/windows/client-management/mdm/policy-csp-update)** [GA] - Intune now supports configuring maintenance windows specifically for OS and driver updates on Windows devices, with controls for start date, time, duration, and repeat schedule. Create profiles under Devices > Manage devices > Maintenance windows. This is the native Intune answer for orgs that need update activity confined to defined change windows without relying on WSUS or third-party tooling.

- **[Configure evaluation frequency for custom compliance scripts on Windows and macOS](https://learn.microsoft.com/en-us/intune/fundamentals/whats-new)** [GA] - Custom compliance script evaluation intervals on Windows and macOS can now be set to 15 minutes, 30 minutes, or one to eight hours, replacing a fixed schedule. Tune this to match your compliance SLA requirements; more frequent checks increase device resource pressure, so test before broad deployment.

- **[CIS benchmark auditing for Windows 11 devices (public preview)](https://learn.microsoft.com/en-us/intune/device-security/security-baselines/cis-audit-baseline)** [Preview] - Intune Advanced Analytics subscribers can now create and assign CIS benchmark audit profiles for Windows 11, review per-setting gap results, and export findings. This is read-only and does not remediate, but it provides structured evidence for compliance reporting against a recognized security benchmark.

- **[Support tip: Why Windows driver recommendations may vary between deployment rings](https://techcommunity.microsoft.com/t5/intune-customer-success/support-tip-why-windows-driver-recommendations-may-vary-between/ba-p/4572700)** [GA] - Windows Update evaluates driver updates independently per deployment ring, which means the same driver can appear as "Recommended" in one ring and "Other" in another, change classification over time, or not appear at all even when the manufacturer lists it. If your teams are troubleshooting inconsistent driver update behavior across rings, this support article documents the expected behavior so you can close unnecessary tickets.

- **[Granular controls for multiple updates in Windows Autopatch](https://techcommunity.microsoft.com/t5/windows-it-pro-blog/granular-controls-for-multiple-updates-in-windows-autopatch/ba-p/4572668)** [Preview] - A single Autopatch quality update policy can now independently manage Windows quality updates, supported .NET Framework updates, and quick machine recovery updates, each with its own automatic or manual approval setting and dedicated device status reporting. Review the blog's guidance on how this interacts with existing policies before enabling; a phased pilot ring evaluation is strongly recommended.

## Security & Compliance

- **[Expanded identity activity visibility in advanced hunting](https://learn.microsoft.com/en-us/defender-xdr/advanced-hunting-schema-tables)** [GA] {{< emphasis "Identity" >}} - Defender XDR advanced hunting now includes additional Active Directory activity: DRSR and GPO update events in IdentityDirectoryEvents, LDAP search and LDAP ping events in IdentityQueryEvents, and Kerberos and LDAP bind extended events in IdentityLogonEvents. Update your custom detection rules and threat hunting queries to take advantage of this expanded telemetry, particularly for lateral movement and directory reconnaissance scenarios.

- **[(Preview) Alert grouping for custom detection rules](https://learn.microsoft.com/en-us/defender-xdr/custom-detection-rules#alert-grouping-preview)** [Preview] - Starting November 17, 2026, custom detection rules in Defender XDR can be configured to group related alerts from the same rule into a single incident using a time frame and matching criteria. This reduces incident noise for high-volume detections; configure grouping settings and test against existing rules before broad adoption.

- **[(Preview) Protect AI assets from trusted-identity attacks](https://learn.microsoft.com/en-us/defender-cloud-apps/protect-github)** [Preview] {{< emphasis "AI" >}} - Defender XDR now includes detections and automated disruption for device code phishing scenarios targeting GitHub Copilot CLI as part of its security-for-AI coverage. Connect the GitHub connector at the Enterprise level for best coverage. Orgs using GitHub Copilot CLI should prioritize this connector setup given the active threat pattern.

- **[(Preview) New navigation in the Microsoft Defender portal](https://learn.microsoft.com/en-us/defender-xdr/microsoft-365-defender-portal)** [Preview] - Microsoft Sentinel pages are being reorganized into the main Defender portal navigation, integrating them into the areas where they're contextually used rather than a separate Sentinel section. If your org is running the Integrated Security Operations Center experience in Defender, review the updated navigation table in the linked docs. Orgs still on the legacy Microsoft Sentinel navigation are unaffected for now.

- **[(Preview) Entity mapping enhancements for custom detection rules](https://learn.microsoft.com/en-us/defender-xdr/custom-detection-rules#expanded-entity-mapping)** [Preview] - Custom detection rules in Defender XDR can now map up to four identifiers per entity and support adding the same entity type more than once, with expanded identifier support for Impacted Assets and Related Evidence fields. Update complex custom rules that previously hit identifier limits to take advantage of richer entity context in generated alerts.

- **[Secure Data at Microsoft Ignite 2026: Plan Your Experience](https://techcommunity.microsoft.com/t5/microsoft-security-community/secure-data-at-microsoft-ignite-2026-plan-your-experience/ba-p/4573071)** [GA] - Microsoft Purview's Ignite 2026 session guide covers data security as AI adoption scales, with sessions on data readiness, management, and protection for Copilot and AI agent workloads. Ignite runs November 17-20 at Moscone Center in San Francisco, with a parallel digital experience. Bookmark the relevant sessions if you're planning Purview or AI data governance work for 2027.

- **[SCKit abuses ScreenConnect to deploy remote access and target technician sessions](https://www.microsoft.com/en-us/security/blog/2026/11/13/sckit-abuses-screenconnect-deploy-remote-access-target-technician-sessions/)** [GA] {{< emphasis "SecOps" >}} - The SCKit threat cluster is abusing ScreenConnect to establish unauthorized remote access and specifically targeting technician sessions, turning your own support tooling into an attack vector. Review the attack chain, hunting queries, and mitigations in the linked blog. If ScreenConnect is in your environment, audit active sessions and restrict access to known-good endpoints immediately.

- **[Plan your Ignite agenda: Securing agentic insiders at scale](https://techcommunity.microsoft.com/t5/microsoft-security-community/plan-your-ignite-agenda-join-sessions-that-help-you-secure/ba-p/4569987)** [GA] {{< emphasis "AI" >}} - Microsoft Security's Ignite sessions focus on Project Perception's expanded capabilities for governing AI agents as a new insider risk category, covering agents that can be manipulated or compromised while operating at machine speed. Worth attending or watching on-demand if you're building an agentic AI security posture.

- **[A next step in the evolution of the Microsoft Data Governance strategy](https://techcommunity.microsoft.com/t5/microsoft-security-community/a-next-step-in-the-evolution-of-the-microsoft-data-governance/ba-p/4572227)** [GA] {{< emphasis "Data" >}} - Microsoft has announced that data governance is moving natively into Microsoft Fabric, with the OneLake catalog becoming the unified governance layer across the enterprise data estate. Organizations with standalone Purview data catalog deployments or roadmaps built around the classic governance tooling should factor this platform shift into their 2027 planning cycles.

- **[Trained to betray: How post-training supply chain attacks hijack coding agents](https://www.microsoft.com/en-us/security/blog/2026/11/12/trained-to-betray-how-post-training-supply-chain-attacks-hijack-coding-agents/)** [GA] {{< emphasis "AI" >}} - Microsoft's AI Red Team published research showing that poisoned datasets or model checkpoints can trigger remote code execution and other malicious behavior in coding agents by modifying fewer than ten neurons in a model. If your org uses fine-tuned or third-party coding agent models, this is a direct prompt to review model sourcing, integrity verification, and your AI supply chain controls.

- **[The global socket: how threat actors are weaponizing GSocket for stealthy C2](https://www.microsoft.com/en-us/security/blog/2026/11/11/global-socket-how-threat-actors-weaponizing-gsocket-stealthy-c2/)** [GA] {{< emphasis "SecOps" >}} - Threat actors are deploying GSocket on compromised Linux servers to maintain encrypted C2 channels after the original vulnerability is patched, creating a persistent backdoor that survives remediation. Review the detection, investigation, and remediation guidance in the blog; include GSocket in your Linux threat hunting queries and EDR exclusion audits.

- **[Lessons from 59 Linux Kernel Bug Reports](https://www.microsoft.com/en-us/security/blog/2026/11/11/lessons-from-59-linux-kernel-bug-reports/)** [GA] - Microsoft's FORGE Lab used AI-assisted research (MDASH) to generate 59 upstream Linux kernel bug reports, resulting in 33 CVEs and 38 merged fixes, including eight demonstrated local root privilege-escalation exploits. Orgs running Linux-based workloads should ensure kernel patching cadences are current, as multiple fixes from this research are now in upstream releases.

- **[Detecting sleeper agents hiding in AI model neurons](https://www.microsoft.com/en-us/security/blog/2026/11/10/detecting-sleeper-agents-hiding-in-ai-model-neurons/)** [GA] {{< emphasis "AI" >}} - Microsoft Research found that an AI agent model can be turned into a sleeper agent by editing fewer than ten neurons to inject a payload, but also that frontier agents can detect these anomalous weight edits. This is early-stage research with no immediate product action, but it reinforces the case for model integrity checks and AI red-teaming before deploying capable agents in production environments.
