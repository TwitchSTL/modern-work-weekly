## Top 5

1. **Agent 365 MCP server governance is GA:** {{< cat "Action Required" >}} {{< reason "Governance Move" >}} Microsoft Agent 365 gives admins a unified console to view all MCP servers, plugins, and connectors in use across the tenant, block risky tools outright, and approve or reject new tool requests before agents act on them. If you have any Copilot Studio or Copilot Chat agents in production, this is your control plane for agent tool access - review it now before your agent estate grows further.

2. **MDE AI agent runtime protection configurable from Intune:** {{< cat "Endpoint & Device Management" >}} {{< reason "Governance Move" >}} A new Intune endpoint security template lets you enforce Audit or Block mode for AI agent runtime activity on Windows, covering both Intune-managed and MDE security settings management devices. This is the enforcement layer for the AI governance posture Microsoft has been building toward - stand up Audit mode first to baseline behavior before moving to Block.

3. **Cloud PKI now available for GCC High tenants:** {{< cat "Endpoint & Device Management" >}} {{< reason "New Capability" >}} Intune Cloud PKI reaches GCC High, removing the last major on-premises dependency for certificate-based authentication in sovereign environments. GCC High tenants can now automate certificate issuance, renewal, and revocation for Wi-Fi, VPN, and app auth without NDES or the Intune Certificate Connector.

4. **EvilTokens device code phishing platform disrupted:** {{< cat "Security & Compliance" >}} {{< reason "Worth Watching" >}} Microsoft DCU, in collaboration with partners, disrupted the EvilTokens PhaaS infrastructure that automated device code phishing with AI-assisted lures and token theft. The threat is real and the TTP is still live elsewhere - if you haven't restricted device code flow in Conditional Access, now is the time.

5. **CVE-2026-81355 VHD Miniport Driver RCE rated Critical:** {{< cat "Action Required" >}} {{< reason "Patch Now" >}} This Critical-rated remote code execution vulnerability in the Virtual Hard Disk Miniport Driver received an acknowledgment update this week. Confirm patched build versions are deployed across your Windows fleet; this affects environments using VHD-backed workloads including Windows 365 and on-premises Hyper-V.

## Identity & Access

- **[Storm-3168: Agentic-driven cloud attacks using compromised service principals](https://www.microsoft.com/en-us/security/blog/2026/09/25/storm-3168-agentic-driven-cloud-attacks-using-compromised-service-principals/)** [GA] {{< emphasis "SecOps" >}} - Service principal compromise is the entry point here: Storm-3168 (JADEPUFFER-linked) uses stolen SP credentials to conduct Azure reconnaissance, delete resources, and harvest additional credentials. Audit your service principal credential hygiene, enable Entra ID's workload identity risk policies, and verify that SP permissions follow least-privilege; over-permissioned SPs are the blast radius multiplier in every documented incident.

- **[Dynamics 365 Field Service: Track costs for non-billable field work](https://www.microsoft.com/microsoft-365/roadmap?id=570857)** [GA] - Field Service Work Orders can now connect to a project as a financial container for internal operational work, letting labor, material, and expense costs flow through project accounting without requiring a separate billing workflow. Relevant if your organization uses Field Service for both customer-facing and internal maintenance work and needs cost visibility without invoice generation.

## Endpoint & Device Management

- **[Microsoft Cloud PKI support for US Government GCC High](https://learn.microsoft.com/en-us/intune/cloud-pki/)** [GA] - GCC High tenants can now build and manage a fully cloud-based PKI through Intune, eliminating the requirement for on-premises CA infrastructure, NDES, or the Intune Certificate Connector. Certificate-based auth for Wi-Fi, VPN, and apps is now fully manageable from the Intune admin center in sovereign cloud.

- **[Faster delivery of Win32 apps](https://learn.microsoft.com/en-us/intune/app-management/ref-protected-apps)** [GA] - Intune now uses push notifications to signal managed devices when admin-initiated or service-side Win32 app changes occur, so devices check in immediately rather than waiting for the next polling cycle. Expect noticeably faster app deployments and updates, particularly in large-scale rollouts where polling lag was a visible issue.

- **[Require Managed Home Screen authentication for protected app activities](https://learn.microsoft.com/en-us/intune/app-management/configuration/configure-managed-home-screen)** [GA] - MAM-integrated apps now redirect users to MHS for sign-in or PIN before allowing access to protected content, preventing authentication bypass at the app layer on Android Enterprise. Assign an app protection policy to both the target app and the signed-in user - no additional policy setting is required to activate the behavior.

- **[Faster Win32 app delivery after Windows enrollment](https://learn.microsoft.com/en-us/intune/device-management/tools/management-extension-windows)** [GA] - The Intune Management Extension now polls for app assignments immediately after the Enrollment Status Page completes, closing the gap where required Win32 apps not installed during ESP would sit idle until the next scheduled check-in. Autopilot-heavy environments with large ESP-excluded app sets will see the most benefit.

- **[New Apple settings in the Settings Catalog for iOS/iPadOS and macOS](https://learn.microsoft.com/en-us/intune/device-configuration/settings-catalog/)** [GA] - The Intune Settings Catalog adds new Apple-sourced options covering app controls, Apple Intelligence, network and web-content filtering, and the macOS login window. If you manage Apple fleets and have been waiting on specific controls for AI features or login window customization, check the catalog for your target OS version.

- **[Assignment filters for Android Settings Catalog policies](https://learn.microsoft.com/en-us/intune/fundamentals/filters/overview)** [GA] - Intune assignment filters now work with Android Enterprise and AOSP Settings Catalog policies, enabling include/exclude targeting based on device properties. This closes a gap that previously required separate policy sets to approximate the same scoping behavior.

- **[Automatically launch Microsoft Defender for Endpoint during Android Enterprise device setup](https://learn.microsoft.com/en-us/intune/device-enrollment/apple/setup-automated-ios#setup-assistant-screen-reference)** [GA] - For corporate-owned Android Enterprise devices, Intune can now automatically open MDE during out-of-box setup so users complete Defender's initial configuration as part of enrollment rather than skipping it. Requires the Defender connector, Grant MTD role permissions toggle, and the Defender app assigned as required before enabling in Endpoint security > Defender for Endpoint.

- **[Upgrade an existing Android Enterprise connection to a managed Google domain](https://learn.microsoft.com/en-us/intune/device-enrollment/android/connect-managed-google-play#upgrade-to-a-managed-google-domain)** [GA] - Tenants that originally connected Android Enterprise with a Gmail account can now upgrade to a managed Google domain and tie the Google-Intune connection to a Microsoft Entra work account. Navigate to Devices > Enrollment > Android > Managed Google Play to start the upgrade; this is optional but recommended for enterprise governance.

- **[Bulk manage eSIMs on corporate-owned Android Enterprise devices](https://learn.microsoft.com/en-us/intune/device-management/inventory-and-status/device-details)** [GA] - Admins can now activate eSIMs on up to 100 corporate-owned Android Enterprise devices at once (Android 15+) via a carrier activation server URL, and bulk wipe operations preserve eSIM data plans by default with an explicit opt-in to remove them. Personally owned work profile devices are excluded from both actions.

- **[Configure MDE AI agent runtime protection for Windows](https://learn.microsoft.com/en-us/defender-endpoint/ai-agent-runtime-protection-overview)** [GA] {{< emphasis "AI" >}} - A new Intune endpoint security template surfaces MDE's AI agent runtime protection settings for Windows, with Audit mode for detection-only visibility and Block mode for pre-execution enforcement. Start with Audit to establish a behavioral baseline before committing to Block, especially in environments where AI-assisted tooling is already embedded in dev or analyst workflows.

- **[Onboard MDM compliance partners with new self-service functionality](https://learn.microsoft.com/en-us/intune/device-security/compliance/third-party-partners#self-service-onboarding-for-compliance-partners)** [GA] - Compliance partners can now self-onboard their connectors using Intune documentation, contracts, and validation hooks, and admins can opt in by providing vendor information directly in the admin center. This expands the ecosystem of third-party compliance solutions available without waiting for Microsoft-managed connector development cycles.

- **[Microsoft Intune and Apple OS 27: New settings, support, and platform changes](https://techcommunity.microsoft.com/t5/intune-customer-success/microsoft-intune-and-apple-os-27-new-settings-support-and/ba-p/4559764)** [GA] - Intune ships day-zero support for Apple OS 27, including new DDM configurations via the Settings Catalog, continued investment in data-driven infrastructure for rapid settings delivery, and compatibility for existing features across iOS/iPadOS and macOS 27. Review the full post for new settings that may need policy coverage in your Apple fleet before OS 27 adoption accelerates.

- **[Giving you more control over camera, microphone, and location](https://techcommunity.microsoft.com/t5/windows-it-pro-blog/giving-you-more-control-over-camera-microphone-and-location/ba-p/4559374)** [GA] - Windows Insiders in the Experimental channel can now manage camera, microphone, and location access on a per-desktop-app basis rather than via a single global toggle. This is an Insider-channel preview only for now; watch for the Intune policy surface when it moves toward broader availability, as it has direct implications for app permission governance.
