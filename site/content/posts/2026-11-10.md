## Top 5

1. **[Microsoft Copilot harness in Copilot Studio now GA for production agents](https://techcommunity.microsoft.com/t5/copilot-studio-blog/more-powerful-agents-and-workflows-for-autonomous-business/ba-p/4542969):** {{< cat "AI & Copilot" >}} {{< reason "New Capability" >}} The Microsoft Copilot harness moves out of preview and into production support, giving Copilot Studio agents a full agentic loop with planning, subagent calls, code execution, and file reasoning. If your org is building autonomous business-process agents, this is the runtime to standardize on; it also ships with per-agent Entra Agent IDs and egress controls, so your governance posture doesn't have to trail your build velocity.

2. **[OAuth authentication now GA for on-premises Exchange mailbox migrations](https://techcommunity.microsoft.com/t5/exchange-team-blog/now-available-oauth-authentication-for-on-premises-exchange/ba-p/4571777):** {{< cat "Collaboration & Productivity" >}} {{< reason "Governance Move" >}} MRS now accepts OAuth in place of Basic auth credentials for on-premises-to-M365 mailbox migrations, closing a long-standing privileged-credential exposure in hybrid migration workflows. If you have outstanding or recurring migration batches running with Basic auth, reconfigure those endpoints now; there's no reason to keep a privileged AD account credential in a migration config going forward.

3. **[Chromium Edge patch batch: multiple CVEs with CVSS up to 9.6](https://msrc.microsoft.com/update-guide/vulnerability/CVE-2026-118321):** {{< cat "Action Required" >}} {{< reason "Patch Now" >}} Thirteen Chromium CVEs landed this week covering use-after-free, memory corruption, integer overflow, and input validation bugs, with four entries scoring 9.6. Severity ratings from MSRC are not yet assigned (Chrome-originated), but CVSS base scores this high in browser primitives warrant an immediate Edge update push across managed endpoints.

4. **[Conditional Access policy plans enter public preview](https://techcommunity.microsoft.com/t5/microsoft-entra-blog/scale-access-controls-with-microsoft-entra-conditional-access/ba-p/4569647):** {{< cat "Identity & Access" >}} {{< reason "Governance Move" >}} Policy plans let you define access intent once and enforce it uniformly across all identities, replacing the sprawl of individually managed CA policies. For large tenants carrying dozens of overlapping policies, this is the structural change worth piloting now so you're positioned to consolidate before GA.

5. **[Threat actors using ARTEX agentic framework to harvest OAuth secrets from GitHub](https://www.microsoft.com/en-us/security/blog/2026/11/05/threat-actors-use-agentic-ai-tooling-to-find-and-abuse-exposed-secrets/):** {{< cat "Identity & Access" >}} {{< reason "Worth Watching" >}} Storm-3358 is actively using an AI-driven offensive framework to scan GitHub repos for exposed OAuth application secrets and then pivot into tenant environments using those compromised app identities. Audit your GitHub repos and CI/CD pipelines for committed OAuth credentials and rotate anything found; also review OAuth app permissions in your Entra tenant for any applications you don't recognize.
